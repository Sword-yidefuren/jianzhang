# 改版判断（2026-11-25）

## 结论

| 想法 | 可行性 | 建议 |
| --- | --- | --- |
| 首页和明细合并 | 高 | 做，能明显减少重复页面 |
| 导航中间加号 + 直接说 / 详细记 | 高 | 做，手机上比底部五个入口清楚 |
| 长按输入框语音转文字 | 中高 | 能做，但不建议绑在输入框长按上；改成「按住麦克风」 |
| 统计按年看 | 高 | 做，月/年切换 |
| 存钱大于 0 就舒服色 | 高 | 做，负数才醒目 |
| 设置页删冗余文字和数据库路径 | 高 | 做，路径移到隐藏的“关于/数据”里即可 |

## 1. 首页和明细合并

建议首页改成：

1. 顶部「记账」标题和本月概览；
2. 存钱目标一行；
3. 月份切换、搜索、收入/支出筛选；
4. 直接接账目列表，按日分组；
5. 删除「花在哪里」和「最近账目」。

这样「明细」不再是独立 Tab，筛选和搜索仍然保留。导入入口放在首页标题右侧的小按钮，不占主流程。

需要接受一个代价：首页会变长，打开时先看到概览，再往下才是账目。这是合理的，因为记账工具的第一眼应该是“本月怎么样”，不是“刚才记了什么”。

## 2. 中间加号与两种记账方式

手机底部改成 4 个 Tab + 中间一个圆形加号：

`记账 | 统计 | ＋ | 存钱 | 设置`

点加号弹出底部面板：

- 上方直接给一句话输入框和实时预览；
- 下方一个「详细记一笔」入口；
- 这样“直接说”和“详细记”都在同一个面板里，不用先选模式再进第二层。

桌面侧栏保留现有的「记一笔」按钮，不加中间悬浮按钮。

### 语音的可行性

可以用 `speech_to_text`（当前 7.5.0，Android / iOS / Windows 都有实现）：

- Android 调系统语音识别，需要 `RECORD_AUDIO` 权限；
- 中文识别效果取决于手机自带的语音服务；
- **不是纯离线**：部分系统语音服务会把音频送到云端，且需要网络；
- Windows 的语音实现依赖系统语音组件，不能保证每台机器可用。

所以语音能做，但和“所有数据只在这台设备”有冲突，必须在界面上写清楚：语音使用系统服务，可能联网；失败就回退到打字。

### 不建议“长按输入框”

长按输入框在手机上是选中文字/弹出复制菜单的手势，直接占用会冲突。更稳的交互是：

- 输入框右侧放一个麦克风按钮；
- **按住说话，松开结束**；
- 说话时显示“正在听…”，识别结果直接填进输入框，仍可修改后再保存。

如果坚持长按输入框，只能做“输入框为空时长按”生效，体验会比较别扭。

## 3. 统计按年看

增加「月 / 年」切换：

- 月：现有逻辑不变；
- 年：自然年 1–12 月，显示年度收支、分类占比、12 个月趋势、记账天数、日均、最大单笔；
- 年视图点某个月的柱子，可以跳回该月。

年度统计直接查 SQLite，不需要新表。

## 4. 存钱颜色

改成：

- 已存 > 0：墨绿色，舒服色；
- 已存 < 0：赤陶色，醒目；
- 已存 = 0：中性灰。

不再用“是否达到目标”决定主数字颜色。目标差额仍然显示，未达到时用次要文字色，不抢主数字。

## 5. 设置页减法

建议删掉/收起：

- `本地数据` 下面的完整数据库路径；
- `96 笔账目 · SQLite` 这类技术说明；
- 关于页的长段落，只留一句“本地优先，不上传、不联网”。

保留：

- 固定月收入；
- 导入账单；
- 导出 CSV；
- 清空账目；
- 版本号。

数据库路径可以放到「关于」里点开再显示，日常设置页不展示。

## 影响范围

- 导航从 5 个入口改成 4 个 + 中间加号；
- 删除独立明细页，首页承担列表；
- 新增语音依赖和 Android 麦克风权限；
- 统计页加月/年状态；
- 设置页删文字；
- 旧数据不受影响。

## 需要你确认的两点

1. 语音是否接受“调用系统语音服务、可能联网”？如果不接受，就只做文字 + 详细记，不加麦克风。
2. 合并后首页 Tab 叫「记账」还是「首页」？我建议「记账」，和产品名一致。

确认后按 1.3.0 做，先改首页/导航，再补语音和年度统计。
